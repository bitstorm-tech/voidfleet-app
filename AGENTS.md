# Voidfleet

Das ist Voidfleet, ein asynchroner PvP-Deckbuilder, der im Science-Fiction-Weltraum-Universum spielt. Der Spieler befehligt eine Flotte aus Raumschiffen. Schiffe werden auf das Spielbrett (zwei Lanes pro Seite: Strike und Command) gelegt und mit Befehlen unterstützt, zum Beispiel Angriff, Reparieren, Schilde aufladen. Schiffe und Befehle werden jeweils als Karte mit unterschiedlichen Werten dargestellt und kommen aus zwei getrennten Decks.

Das Besondere an Voidfleet ist der asynchrone Spielmodus mit Simultaneous Blind Play: Beide Spieler wählen ihren Zug gleichzeitig und blind, ohne Timer — ein Zug darf beliebig lange dauern. Vor der ersten Runde wählt jeder verdeckt einen von fünf Admiralen (die Mauer, der Hammer, der Schwarm, das Phantom, der Uhrmacher). Jeder bringt sein Flaggschiff mit, ein Kampfschiff mit eigener Fähigkeit, das er in Runde 1 zusätzlich legt, und eine Admiralsfähigkeit. Ein Zug besteht aus bis zu 1 Schiff (in Runde 1 zwei plus Flaggschiff), 1 Befehl und entweder einem Grundmanöver oder der Admiralsfähigkeit: Beim Grundmanöver wechselt ein Schiff auf dem Brett in einen freien Slot, in der anderen oder derselben Lane, und feuert dafür in dieser Runde nicht. Dazu gibt der Spieler jedem seiner Kampfschiffe einen Feuerbefehl: das gegnerische Schiff, auf das es im Kampf feuert; ohne Feuerbefehl feuert es nicht, eine automatische Zielwahl gibt es nicht. Sobald beide submitted haben, wird aufgedeckt und in festen Phasen aufgelöst (Deploy → Manöver → Effects → Combat → Cleanup). Wessen Flaggschiff zerstört wird, hat verloren, fallen beide in derselben Runde, ist es unentschieden; ab Runde 8 bekommen alle Kampfschiffe Overdrive (+1 ATK, alle 4 Runden einen mehr), damit Partien nicht im Patt enden. Es gibt kein Energie-/Mana-System.

## Status

Wir sind momentan noch in der Entwicklungsphase. Das Spiel ist also nicht live. Aus diesem Grund können wir den Code jederzeit komplett ändern und es ist nicht notwendig, defensiven Code, Kompatibilitätslayer oder Sonstiges zu implementieren. Wir müssen also keine Rücksicht auf Legacy Code nehmen, sondern können den Code so einfach, schlank und elegant wie möglich halten.

## Linting und Formatierung

Biome für das ganze Repo (`biome.json` und `package.json` im Wurzelverzeichnis, einmal `bun install`): `bun run lint` prüft Lint, Formatierung und Import-Reihenfolge, `bun run fix` behebt, was sich automatisch beheben lässt. Nach Änderungen `bun run fix` laufen lassen; `bun run lint` muss ohne Befund durchgehen, zusammen mit `bun run typecheck` in `client/` und `server/`. Abgeschaltet sind Regeln, die gegen bewusste Muster im Code gehen: `!` nach Indexzugriffen (wegen `noUncheckedIndexedAccess`), `return f()` in `void`-Funktionen, Zuweisungen in Ausdrücken, Fallthrough (prüft TypeScript) und in CSS `!important` und absteigende Spezifität.
